# 本地视频分析

WormVision 沿用采集、视频库和深浅主题，视频由随软件分发的 MicroHunter 发行引擎在本机处理。

## 使用流程

1. 首次使用打开“本地分析 → 许可与激活”，输入发行引擎的有效激活码。
2. 在“采集”页完成录像，等待录像保存结束。
3. 打开“视频库”，勾选需要分析的视频；未勾选时使用选中的表格行。
4. 点击“分析选中”，进入“本地分析”。
5. 选择“固体爬行”或“液体摆动”，计算设备通常保持“自动”。有实测标定时填写 mm/px，没有时保持未启用。
6. 点击“开始分析”。算法固定为 `yolo-sam2-optimized-core`，同时生成标注回放。
7. 完成后查看汇总、逐视频逐虫指标和轨迹图，或打开标注视频、Excel、PDF及结果目录。

录像保存期间禁止提交分析、删除/重命名视频及更换保存位置；分析进行时也保护视频库文件操作。
停止录像后会等待文件大小连续约 600ms 稳定且 AVI 头可解析出时长，约 6 秒仍无法确认则提示。
该检查不替代完整视频解码校验。取消请求由引擎在处理检查点响应；退出时若任务未完成，会询问是否结束。

## 发行引擎与激活

使用维护者提供的完整 `microhunter.7z`，解压布局与命令见 [README](../README.md)。
软件按以下顺序查找发行引擎：

1. “引擎设置”中保存的发行版 exe。
2. 程序目录的 `engine/microhunter.exe` 或 `engine/microhunter/microhunter.exe`。

必须保留 `_internal`、`weights` 及发行包的其他运行依赖，不能只复制 exe。
1.1.2 不再运行 Python 入口或自动发现相邻源码仓库，升级时忽略旧 Python/脚本配置。
引擎需要支持 `api_version: 1`；仅有旧 CLI 的发行包不兼容。

“开始分析”仅在引擎报告许可有效时启用。“许可与激活”把激活请求交给发行引擎；Qt 不自行验证或绕过许可。
视频不上传；激活和续期沿用引擎已有联网规则。机器许可、设置和激活资料不加入 Git。

发行包保持原样。本项目不向其注入此前源码模式的 YOLO 单精度补丁，也不修改加密模型。
此前源码模式的成功分析记录只证明当时源码环境可用，不能作为该发行包已完成推理验证的依据。

2026-09-04 的原始发行包在 GTX 1660 Ti 上执行实际视频时，已确认在 vision 第一帧报错 `Observation.bbox coordinates must be finite`。当时许可有效，自动设备参数提交正确；发行接口拒绝未声明的 `half` 参数。该问题尚未修复，CPU 回退也未验证成功。配套 Release 保留原包用于构建复现，不作为已修复的分析版本。

## 数据与结果

- Qt 通过 `QProcess` 启动自己的引擎进程，绑定 `127.0.0.1` 随机端口，检查 API 版本后读取许可和任务。
- 工作区位于应用用户数据目录的 `analysis` 下，Windows 通常是 `%LOCALAPPDATA%/WormLab/WormVision/analysis`。
- 结果位于工作区 `outputs/<run>/` 下，包括 `results/metrics.json`、Excel、`qc/trajectory`、`qc/review` 和 `report`。
- 指标表直接读取引擎的中文列名、单位及数值；`null` 和缺失值显示为 `—`，Qt 不重新计算科研指标。
- 当前百分比属于引擎正在执行的阶段，进入下一阶段可能重新计数。
- 内存任务使用 `job_id`，历史记录保存在引擎工作区，页面重启后从历史读取。
- 图片在页面内预览，视频、Excel和PDF由系统默认程序打开。

“自动”计算设备不提交字符串 `auto`，由发行引擎选择 CUDA 或 CPU；手动选择则传 `cuda:0` 或 `cpu`。
如果仍出现 GPU 或推理错误，应保留实际报错并检查发行引擎兼容性，不应绕过数据校验。
提交请求中断导致无法确认是否已入队时，Qt 会停止自己的引擎，避免任务在后台继续执行。

## 实现与验证范围

主要代码位于 `LocalAnalysisService`、`AnalysisWidget` 和 `AnalysisResults`，沿用原有主窗口、视频库及录制忙状态。
展示组织参考云端结果页，本地使用发行引擎现成的轨迹图、标注视频和报告。

定向测试覆盖视频选择和录像保护、指标解析、设备参数、旧源码配置迁移、未授权禁用提交、引擎握手和 HTTP 错误。
在构建完成后执行：

```powershell
ctest --test-dir build --output-on-failure -R '^(test_video_library_widget|test_analysis_results|test_local_analysis_service)$'
```

这些测试使用隔离的本地测试服务，不执行模型；真实视频推理需要有效发行许可。
真实相机录制仍需按 `docs/SMOKE_TEST.md` 连接设备确认。
